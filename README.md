# Elevation Atlas

A static, dependency-free WebGPU heightmap explorer. Open `index.html` with your live server, or run `npm start` and visit http://localhost:8080. WebGPU requires localhost or HTTPS and a supported browser/GPU.

- Drag, scroll, pinch, or focus the map and use arrow keys / + / −. Releasing a moving drag adds a gentle coast using SST point-cloud damping (0.966 per 60 Hz frame), integrated in elapsed time. A new drag, wheel event, keyboard action, cancellation, or loss of window focus stops it; reduced-motion preferences disable it.
- Use the Flat / Sphere toggle and fullscreen button on the right of the header. The map section itself is entirely canvas; position, scale, instructions, and loading status live in the sidebar. The adjacent fullscreen icon expands only the canvas, without toolbar, messages, borders, or padding; Escape exits. Sphere uses analytic orthographic ray projection per device pixel, with a camera-culled Mercator quadtree. A tile subdivides until its worst-case projected texel is at most one device pixel (or reaches the source zoom ceiling); latitude and the full device pixel ratio are included. A GPU tile-array atlas and hash page table sample the visible leaves directly, with stable residency while rotating. A coarse root tile fills the globe while native-resolution leaves stream in, prioritized from the center outward. Drag to rotate, scroll/pinch to zoom, with the same momentum as flat mode. Auto-exposure reduces only visible globe heights, and HDR, water masking, highlights, and source-aware edges are shared with the flat renderer. Provider coverage stops near ±85.05° latitude, leaving the small polar caps without data. The globe atlas is additional to the tile-cache memory budget.
- Every slider has a text-like number field inline with its title, a neighboring unit, and separate increase/decrease buttons. Lock and fullscreen SVGs use explicit flex centering. Editing an elevation limit locks it. Locked sliders dim while remaining manually adjustable. Highlight elevation and width controls are disabled when Highlight is off (hover previews temporarily enable them). The compact cool-white UI is constant across color maps.
- Each unlocked elevation limit follows valid visible samples independently. Click its lock icon to the right of the slider to hold it; moving a slider locks it automatically. Water is off by default; enabling it includes Seascape-classified water in rendering and automatic exposure. This does not change either limit or lock. Land below sea level remains visible. Edge highlighting is enabled by default.
- Use the rotate-arrow button beside the palette selector to reverse its colors; elevation labels and pinned highlights stay anchored to the same elevations. Thermal is the default; Grayscale maps the range to 0–100% gray, and Antarctica is also available. Thermal and Antarctica retain SST’s palette color science and saturation targets. Hover over the color strip to preview, click/drag to pin an elevation, or uncheck Highlight (or press Escape on the strip) to turn it off. Arrow keys and Home/End also select a highlight. While hovering, an elevation label sits directly beneath the selected point of the color strip; its tick remains anchored and the text stays inside the strip bounds. The persistent label reports the pinned elevation and band limits.
- Highlight centers are stored in meters, independent of exposure. Half-width is stored as a fraction of the current color-map range, defaulting to 1/8 (12.5%). The lock beside Half-width holds H constant in meters across exposure changes; unlock it to resume proportional scaling from the current width. Locked widths remain manually editable. The meter value H is otherwise recalculated as `(max − min) × fraction` whenever exposure changes, including zoom and Water. Adjust Highlight half-width to set the meter width for the current view; that choice updates the retained fraction, so the same portion of the scale remains highlighted in subsequent views. All palettes use the same weight `max(0, 1 − abs(elevation − center) / H)²` in OKLab: weight 1 at the center, 0.25 halfway to a boundary, and 0 at center ± H. Thus the full support width is 2H, and full width at half maximum is `2H × (1 − 1/√2) ≈ 0.5858H`. The center remains fixed when zooming, panning, changing palettes, or adjusting exposure—even when the selected elevation lies outside the color scale. H scales with exposure; changing palettes alone does not change it. Grayscale targets an HDR neutral highlight in the same perceptual blend space.
- Edge highlighting computes SST’s 3×3 Sobel magnitude on the source-texel grid, then bilinearly interpolates it alongside elevation. Flat and globe views share a 16-load neighborhood for four source stencils; gradients are never computed from the screen-resampled height field. Tile-edge derivatives use one-sided spacing correction, and water/nodata neighbors cannot create false shoreline edges. The existing two-channel float target carries elevation and raw edge strength, so there is no additional GPU texture/cache allocation. Exposure normalization stays in the color shader; previews suppress edge shading and strength zero skips source-gradient reads. The checkbox animates over half a second with sine easing.
- Both visible canvases use `border-radius: 1px 0 0 0` for Chrome HDR compositing.
- Presentation follows SST's `rgba16float`, Display P3, extended tone mapping approach, with standard/preferred-format fallbacks. Actual HDR output depends on browser, OS, and display support; telemetry reports the requested presentation mode.
- Canvas dimensions use the full device pixel ratio, without SST's 2× cap. Source zoom is `ceil(viewZoom + log2(DPR × 256 / tileSize))`, capped by provider limits. Thus source texels are at least as dense as device pixels until the source limit. Float32 DEM heights are bilinearly reconstructed for display without interpolating across land/water classes or missing samples. Source spacing is retained with the classification in a compact second channel, so overzoomed parent tiles use their effective source spacing. Higher tile levels cannot add detail beyond the source surveys.
- Tiles are fetched and decoded in a worker with bounded concurrency, obsolete requests are cancelled, and non-visible GPU tile textures are evicted under a 256 MiB budget. No access keys, framework, build, or Sites hosting required.
- Auto-exposure uses a 500 ms sine-based response. While dragging, coasting, zooming, or navigating with keys, it carries phase across target updates up to the midpoint, then holds the midpoint response rate. After motion stops it completes the slow-out half. Measurements no longer restart the slow-in step; asynchronous GPU results from recent views are accepted in order, while results from an obsolete Water/projection setting are rejected. Elapsed-time integration gives consistent behavior at 60/120 Hz; locked limits and manual edits remain immediate. Reduced-motion preferences disable the animation. The flat renderer keeps the closest cached parent tile visible while detailed tiles stream in, cropping its correct region rather than clearing to black.
- Automatic exposure reduces the visible, ocean-masked device-pixel heights in a GPU compute shader. Only compact per-workgroup extrema are asynchronously read back, and stale results are discarded. Manual slider edits update shader uniforms without CPU elevation scans. Height textures are reused for color/slider/highlight changes, canvas dimensions change only on resize, and view updates are coalesced to animation frames.
- Wheel/pinch zoom anchors to the cursor in both projections. Sphere anchoring solves for the new globe center while keeping the same surface point at the same screen location; outside-globe/polar constraints fall back to center zoom. Hold arrow keys or WASD to pan/rotate continuously at 720 CSS pixels/second, twice the previous speed; hold +/− to zoom continuously, with acceleration and deceleration. Keyboard movement is ignored while editing controls and stops on blur.
- Flat-map panning clamps the viewport edges to the Mercator north/south bounds, rather than merely clamping its center. Zoom cannot go below the scale needed to fit the map height; resize and fullscreen reapply the same constraints. Longitude continues to wrap.
- Location and zoom persist in the URL hash.

## Data

Mapterhorn: https://mapterhorn.com/data-access/ and https://mapterhorn.com/attribution

Open Waters Seascape: https://github.com/openwatersio/seascape/blob/main/docs/schema.md and https://openwaters.io/charts/seascape#license

Both sources use lossless 512px Terrarium tiles. TileJSON is requested at runtime; known endpoint defaults are used if metadata is unavailable. Seascape schema 1 is required. Measured negative Seascape depths take precedence; its land category uses Mapterhorn relief. Unknown-depth water falls back to valid Mapterhorn elevation (often the lake surface, not lakebed bathymetry), including in automatic exposure. Its water classification is retained, so it remains hidden when Water is off. Drying foreshore and fractional non-negative shoreline codes also fall back to Mapterhorn, rather than creating missing-data bands along coasts. Only measured negative Seascape values override Mapterhorn. Water masking still rounds non-negative categories per the schema. A missing (HTTP 404) source tile falls back to its nearest available ancestor; telemetry counts these parent tiles. Other failed provider requests leave the tile blank and report incomplete coverage rather than inventing data. Failed requests retry automatically.

Land elevations and bathymetry have differing vertical datums. This is a visualization, not a seamless geodetic DEM or navigation chart.

Visible terrain requests time out after 1 second and retry immediately. Other failures retry with a 1–30 second exponential backoff. Retries refresh the HTTP cache; leaving the view cancels pending retries. Temporary parent-tile previews skip edge enhancement to avoid bright loading artifacts. The canvas status remains visible in fullscreen.

Zoom stops when one CSS pixel matches one texel of the finest global source level (512-pixel tiles at z18 give flat view zoom 19). The sphere uses the equivalent equatorial CSS radius, independent of region, latitude, and DPR; resizing recalculates its ceiling. Full device-pixel rendering is retained.

Edge gradients use unclipped elevation differences, avoiding hard contour cutoffs at exposure bounds. Globe sampling uses an integer camera-relative tile origin and stable small-angle calculations to retain native texel precision at high zoom. GPU regressions check distinct adjacent samples and identical terrain shading across canvas resizes in both projections.

A compact bottom-right canvas overlay reports cursor coordinates and bilinearly sampled native elevation in both projections, including fullscreen. Pinned locations stay fixed while panning and zooming, and elevation refreshes as finer tiles arrive. Fullscreen has a top-right exit button as well as Escape. CPU/GPU tile storage shares the 256 MiB cache budget.

Hover and pinned locations have independent, labeled coordinate/elevation readouts with matching type sizes. The overlay appears only when hovering or a pin exists; hover and pinned rows are shown as needed. Loading messages remain at the lower left, wrapping above location readings on narrow screens. Sidebar switches retain full-row click targets with compact, unboxed styling.

## Map mode

Map mode adds OpenFreeMap/OpenMapTiles vector roads, administrative boundaries, and place/street labels from OpenStreetMap in both projections. It defaults off and starts no map requests until enabled. Roads provide a separate coverage mask to the WebGPU color shader, which desaturates and brightens the underlying terrain; boundaries use cool blue and labels use a tiered ice-blue palette, with opaque dark halos and a final RGBA glyph layer. The elevation texture, exposure reduction, and highlight math are unchanged by map mode.

Vector fetching, decoding and curve subdivision run in a worker with cancellation, retries and a bounded vector-data cache (64 MiB estimated budget, including segment buffers mirrored on the GPU). Immutable segment buffers are uploaded once. WebGPU projects and rasterizes roads/borders into a full-device-pixel mask, with shader-controlled visibility, fixed-width antialiased round strokes and hemisphere clipping. Labels use instanced GPU sprites from a device-resolution text/halo atlas; Canvas text rasterization only occurs on atlas misses, font completion or DPR changes. CPU work during panning is limited to tile management, label anchors/collision placement and indexed road-context checks. GPU masks and glyph textures are reused during exposure/highlight changes; no full-screen Canvas images are uploaded each pan frame. Geometry overzooms the provider's highest vector level (currently 14), with fixed CSS-size line widths and text. Terrain retains its independent native-resolution limit. No key, build step or map-rendering dependency is required. The local decoder follows [MVT 2.1](https://github.com/mapbox/vector-tile-spec/tree/master/2.1); live metadata comes from [OpenFreeMap](https://github.com/hyperknot/openfreemap). Map attribution is displayed in the sidebar.

Map rendering checks: `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/map-webgpu.mjs` validates worker fetching/decoding, full-DPR masks, line/text channels, collision labels, globe clipping, mask reuse, and toggle behavior. Set `LIVE_MAP=1` to also preview the public vector service in both projections. Roads taper near the globe limb; labels remain upright and are kept inside the globe silhouette.

Road shading is a relative 3× luminance boost with partial (50%) desaturation at full coverage, with no fixed gray brightness target. State/province labels start with state borders at zoom 5 and wait for boundary data. City labels start at zoom 6, towns at 9, and villages at 11; settlement labels additionally require a rendered road within 24 CSS pixels of their anchor, so names do not precede their local road context.

Roads and local labels (settlements, streets, water names) appear one zoom level later, requiring twice the magnification. Country/state borders and their labels retain their existing visibility thresholds.

Map label hierarchy prioritizes continents/countries, then states/provinces, then cities, towns and local names. Administrative labels use modestly larger, regular-weight Rajdhani; settlements use smaller IBM Plex Mono lettering with tracked city capitals. Cool blue administrative boundaries and uniform HDR ice-blue label color match the dashboard. A separate RGBA glyph texture is composited last, over opaque dark label halos, so roads and terrain never show through label interiors.

Road and boundary strokes are half their initial widths. Country/state typography is lighter and smaller, with restrained letter spacing and a thinner opaque halo.

Map lettering uses locally bundled Rajdhani for administrative names and IBM Plex Mono for settlements and street names, with licenses in `fonts/`. The first label placement waits for both local fonts. Grayscale converts all map ink and halos to neutral gray in the shader; Thermal and Antarctica share the cool-blue scheme. All label tiers share the same blue tint. Map ink is luminance-normalized to 1.15× reference white in HDR (blue channels may exceed 1); SDR uses a gamut-safe pastel fallback at 0.88 luminance. Palette changes recolor map ink immediately without re-fetching or re-rasterizing geometry.

The sidebar search accepts decimal latitude/longitude, N/S/E/W coordinates, or degree/minute/second notation, with no network request for coordinates. Address/place searches are submitted to [Photon](https://photon.komoot.io/) on Enter/button press only; ambiguous matches show a short selectable list. Search centers and zooms either projection, fitting provided result bounds where available. Map labels is in View & Rendering; its loading/error status shares the canvas status area with terrain, including fullscreen.

Globe road projection uses camera-relative tile coordinates and a local latitude expansion at deep zoom to avoid float32 banding. Source curves are subdivided once before upload. GPU strokes discard zoom-hidden classes, clip the rear hemisphere and fade roads near the globe limb. Settlement-road context queries the immutable source grid, checking the label’s own tile and nearest cells first, with the same 24 CSS pixel proximity rule. Map masks and text remain at full device-pixel resolution. The glyph atlas is bounded and repacks the active view when full. `tests/map-webgpu.mjs` also checks cached geometry/glyph reuse and native-zoom road alignment across resizes at latitudes 0°, 40°, 80° and −70° in both projections.

## Terrain storage and uploads

Terrain tiles, the globe array atlas, and the elevation target use `rg32float` (8 bytes/texel), preserving native floating-point elevations and water/texel-spacing metadata. Auto exposure reduces the rendered elevation target on the GPU. Native float arrays remain on the CPU for hover and pinned readings; no quantization or exposure-dependent texture conversion is needed.

Stalled terrain requests retry after one second. Repeated timeouts extend the attempt deadline to two, four, then eight seconds so slower downloads can finish instead of restarting indefinitely.

Uploads are staged at most two new textures per moving frame or four while idle. Touch devices use three concurrent tile loads and a 64 MiB retained terrain-cache budget (desktop: four loads and 192 MiB). Visible tiles and active parent previews are preserved even if they exceed that budget. Offscreen GPU copies are released promptly; native CPU data remains available until cache eviction. Sphere terrain uses eight independently growing atlas pages, copying existing layers on the GPU rather than rebuilding one large atlas. HDR presentation, map labels, and the legend keep their existing color capabilities.

Available color maps: Grayscale, Thermal (default), Arctic Ocean (formerly Antarctica), Spirit (formerly Polar Haunt), and Hawaii (formerly Tropical Fire). All palettes support HDR output, reversal, and elevation-based highlighting.

Auto Color Range is on by default and hides the elevation limits. Switching it off reveals and locks both limits at their current values. Individual locks still allow one bound to follow the view; unlocking both turns Auto Color Range back on and hides the limits.

Elevation and Highlight controls expand/collapse with a short slide transition (disabled for reduced motion). Locked limits remain fully editable and visually enabled: their locks pause automatic adjustment only. Search, palette selection, and numeric editors use subtle background fills instead of underlines.

Auto Slider Range appears with the manual elevation controls and defaults on. Slider domains follow native visible elevation bounds independently of locked color limits; disabling it eases the domains back to −12,000…9,000 m over 500 ms. Domains expand to retain selected values outside the current view, so native range-input clamping cannot silently change locked numbers. All slider locks sit beside their numeric editors.

`PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/terrain-gradient-webgpu.mjs` checks source-grid Sobel values against a CPU reference through fractional pans near zoom 5.984, multiple DPRs/zooms, tile boundaries, globe motion, water/nodata masks, previews, and off/on transitions. Flat source UVs are calculated from device-pixel positions to avoid subpixel rasterizer snapping.

## HDR image downloads

The header download button saves the current GPU-rendered view as an HDR AVIF at the canvas's actual device-pixel dimensions. It captures a fresh `rgba16float` target before presentation, so it also avoids precision loss from an SDR canvas-format fallback. Terrain, palette/highlights, and GPU-rendered roads/labels are included; sidebar, legend, DOM pin marker, and other UI overlays are excluded.

The export worker converts the actual render gamut into P3-D65 RGB with ST 2084 PQ, using reference white of 203 nits. AVIF uses 12-bit full-range identity-matrix 4:4:4 coding at quality 100: compression is lossless for the quantized PQ samples, with no chroma subsampling, image resizing, tone mapping, or SDR conversion. As with any fixed-bit-depth HDR format, conversion to 12-bit PQ introduces quantization; PQ represents channel levels up to 10,000 nits. Actual display brightness depends on the viewer/display. Both AVIF container and AV1 sequence-header color descriptions are set consistently (CICP 12/16/0).

The pinned `@jsquash/avif` 2.1.1 encoder and its license notices are in `vendor/avif`. Encoder assets load only on download, and the worker is terminated afterward to release its memory. Encoding stays entirely on the device, without a server or cross-origin isolation. Export status appears on the canvas while the app remains usable. HDR AVIF decoding/display requires a compatible viewer; an SDR display/viewer may tone-map it.

`PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/hdr-export-webgpu.mjs` exercises actual downloads in flat/sphere views at DPR 2 and independently verifies dimensions, 12-bit output, P3/PQ metadata, and pixel samples above reference white with the browser AVIF decoder.
