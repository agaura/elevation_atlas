# Elevation Atlas

A static, dependency-free WebGPU heightmap explorer. Open `index.html` with your live server, or run `npm start` and visit http://localhost:8080. WebGPU requires localhost or HTTPS and a supported browser/GPU.

- Drag, scroll, pinch, or focus the map and use arrow keys / + / −. Releasing a moving drag adds a gentle coast using SST point-cloud damping (0.966 per 60 Hz frame), integrated in elapsed time. A new drag, wheel event, keyboard action, cancellation, or loss of window focus stops it; reduced-motion preferences disable it.
- Use the Flat / Sphere toggle and fullscreen button on the right of the header. The map section itself is entirely canvas; position, scale, instructions, and loading status live in the sidebar. The adjacent fullscreen icon expands only the canvas, without toolbar, messages, borders, or padding; Escape exits. Sphere uses analytic orthographic ray projection per device pixel, with a camera-culled Mercator quadtree. A tile subdivides until its worst-case projected texel is at most one device pixel (or reaches the source zoom ceiling); latitude and the full device pixel ratio are included. A GPU tile-array atlas and hash page table sample the visible leaves directly, with stable residency while rotating. A coarse root tile fills the globe while native-resolution leaves stream in, prioritized from the center outward. Drag to rotate, scroll/pinch to zoom, with the same momentum as flat mode. Auto-exposure reduces only visible globe heights, and HDR, water masking, highlights, and source-aware edges are shared with the flat renderer. Provider coverage stops near ±85.05° latitude, leaving the small polar caps without data. The globe atlas is additional to the tile-cache memory budget.
- Every slider has a text-like number field inline with its title, a neighboring unit, and separate increase/decrease buttons. Lock and fullscreen SVGs use explicit flex centering. Editing an elevation limit locks it. Locked sliders dim while remaining manually adjustable. Highlight elevation and width controls are disabled when Highlight is off (hover previews temporarily enable them). The compact cool-white UI is constant across color maps.
- Each unlocked elevation limit follows valid visible samples independently. Click its lock icon to the right of the slider to hold it; moving a slider locks it automatically. Water is off by default; enabling it includes Seascape-classified water in rendering and automatic exposure. This does not change either limit or lock. Land below sea level remains visible. Edge highlighting is enabled by default.
- Use the rotate-arrow button beside the palette selector to reverse its colors; elevation labels and pinned highlights stay anchored to the same elevations. Thermal is the default; Grayscale maps the range to 0–100% gray, and Antarctica is also available. Thermal and Antarctica retain SST’s palette color science and saturation targets. Hover over the color strip to preview, click/drag to pin an elevation, or uncheck Highlight (or press Escape on the strip) to turn it off. Arrow keys and Home/End also select a highlight. While hovering, an elevation label sits directly beneath the selected point of the color strip; its tick remains anchored and the text stays inside the strip bounds. The persistent label reports the pinned elevation and band limits.
- Highlight centers are stored in meters, independent of exposure. Half-width is stored as a fraction of the current color-map range, defaulting to 1/8 (12.5%). The lock beside Half-width holds H constant in meters across exposure changes; unlock it to resume proportional scaling from the current width. Locked widths remain manually editable. The meter value H is otherwise recalculated as `(max − min) × fraction` whenever exposure changes, including zoom and Water. Adjust Highlight half-width to set the meter width for the current view; that choice updates the retained fraction, so the same portion of the scale remains highlighted in subsequent views. All palettes use the same weight `max(0, 1 − abs(elevation − center) / H)²` in OKLab: weight 1 at the center, 0.25 halfway to a boundary, and 0 at center ± H. Thus the full support width is 2H, and full width at half maximum is `2H × (1 − 1/√2) ≈ 0.5858H`. The center remains fixed when zooming, panning, changing palettes, or adjusting exposure—even when the selected elevation lies outside the color scale. H scales with exposure; changing palettes alone does not change it. Grayscale targets an HDR neutral highlight in the same perceptual blend space.
- Edge highlighting uses SST’s 3×3 Sobel operator and linear-light contrast curve with a source-aware footprint: one device pixel while source samples are finer than the display, expanding to one effective source texel when overzoomed (including parent-tile fallbacks). The filter samples the assembled screen height texture across tile boundaries. Fractional sample locations are interpolated. At strength 0 the shader skips all neighbor reads. Missing samples and zero-range neighbors do not create false coastline highlights. The Edge highlighting checkbox animates the internal strength between 0 and 1 over half a second with sine easing; no strength slider or 0–1 label is exposed.
- Both visible canvases use `border-radius: 1px 0 0 0` for Chrome HDR compositing.
- Presentation follows SST's `rgba16float`, Display P3, extended tone mapping approach, with standard/preferred-format fallbacks. Actual HDR output depends on browser, OS, and display support; telemetry reports the requested presentation mode.
- Canvas dimensions use the full device pixel ratio, without SST's 2× cap. Source zoom is `ceil(viewZoom + log2(DPR × 256 / tileSize))`, capped by provider limits. Thus source texels are at least as dense as device pixels until the source limit. Float32 DEM heights are bilinearly reconstructed for display without interpolating across land/water classes or missing samples. Source spacing is retained with the classification in a compact second channel, so overzoomed parent tiles use their effective source spacing. Higher tile levels cannot add detail beyond the source surveys.
- Tiles are fetched and decoded in a worker with bounded concurrency, obsolete requests are cancelled, and non-visible GPU tile textures are evicted under a 256 MiB budget. No access keys, framework, build, or Sites hosting required.
- Auto-exposure uses a 500 ms sine-based response. While dragging, coasting, zooming, or navigating with keys, it carries phase across target updates up to the midpoint, then holds the midpoint response rate. After motion stops it completes the slow-out half. Measurements no longer restart the slow-in step; asynchronous GPU results from recent views are accepted in order, while results from an obsolete Water/projection setting are rejected. Elapsed-time integration gives consistent behavior at 60/120 Hz; locked limits and manual edits remain immediate. Reduced-motion preferences disable the animation. The flat renderer keeps the closest cached parent tile visible while detailed tiles stream in, cropping its correct region rather than clearing to black.
- Automatic exposure reduces the visible, ocean-masked device-pixel heights in a GPU compute shader. Only compact per-workgroup extrema are asynchronously read back, and stale results are discarded. Manual slider edits update shader uniforms without CPU elevation scans. Height textures are reused for color/slider/highlight changes, canvas dimensions change only on resize, and view updates are coalesced to animation frames.
- Wheel/pinch zoom anchors to the cursor in both projections. Sphere anchoring solves for the new globe center while keeping the same surface point at the same screen location; outside-globe/polar constraints fall back to center zoom. Hold arrow keys or WASD to pan/rotate continuously at 720 CSS pixels/second, twice the previous speed; hold +/− to zoom continuously, with acceleration and deceleration. Keyboard movement is ignored while editing controls and stops on blur.
- Flat-map panning clamps the viewport edges to the Mercator north/south bounds, rather than merely clamping its center. Zoom cannot go below the scale needed to fit the map height; resize and fullscreen reapply the same constraints. Longitude continues to wrap.
- Location and zoom persist in the URL hash.

## Data

Mapterhorn: https://mapterhorn.com/data-access/ and https://mapterhorn.com/attribution

Open Waters Seascape: https://github.com/openwatersio/seascape/blob/main/docs/schema.md and https://openwaters.io/charts/seascape#license

Both sources use lossless 512px Terrarium tiles. TileJSON is requested at runtime; known endpoint defaults are used if metadata is unavailable. Seascape schema 1 is required. Measured negative Seascape depths take precedence; its land category uses Mapterhorn relief. Unknown-depth water falls back to valid Mapterhorn elevation (often the lake surface, not lakebed bathymetry), including in automatic exposure. Its water classification is retained, so it remains hidden when Water is off. Drying foreshore and fractional non-negative shoreline codes also fall back to Mapterhorn, rather than creating missing-data bands along coasts. Only measured negative Seascape values override Mapterhorn. Water masking still rounds non-negative categories per the schema. A missing (HTTP 404) source tile falls back to its nearest available ancestor; telemetry counts these parent tiles. Other failed provider requests leave the tile blank and report incomplete coverage rather than inventing data. Failed requests retry automatically.

Land elevations and bathymetry have differing vertical datums. This is a visualization, not a seamless geodetic DEM or navigation chart.

## Checks

`npm test` checks decoding, categorical handling, full-DPR zoom selection, wrapped/polar coverage, SST momentum damping, frame-rate independence, and fixed-elevation highlight mathematics, half-second sine transitions and midpoint exposure tracking at 60/120 Hz, globe camera bases, projected texel density, and quadtree coverage across the dateline.

Optional Chrome GPU integration checks: install Playwright separately, then run `PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node tests/webgpu.mjs`. These check synthetic exposure bounds, ocean masks, negative land, immediate recoloring, and source-aware edges and interpolated heights on overzoomed tiles, consistent highlight support in all palettes, and pinned-elevation UI behavior, globe atlas sampling/visible exposure, numeric entry, highlight disabling, fixed UI colors, icon locks, number steppers, fullscreen, defaults, parent-tile cropping, hover-label alignment, icon centering, cursor-anchored zoom, continuous keyboard navigation, exposure updates during active panning, viewport bounds, the canvas-only panel/header layout, and Escape fullscreen.

Visible terrain requests time out after 1 second and retry immediately. Other failures retry with a 1–30 second exponential backoff. Retries refresh the HTTP cache; leaving the view cancels pending retries. Temporary parent-tile previews skip edge enhancement to avoid bright loading artifacts. The canvas status remains visible in fullscreen.

Zoom stops when one CSS pixel matches one texel of the finest global source level (512-pixel tiles at z18 give flat view zoom 19). The sphere uses the equivalent equatorial CSS radius, independent of region, latitude, and DPR; resizing recalculates its ceiling. Full device-pixel rendering is retained.

Edge gradients use unclipped elevation differences, avoiding hard contour cutoffs at exposure bounds. Globe sampling uses an integer camera-relative tile origin and stable small-angle calculations to retain native texel precision at high zoom. GPU regressions check distinct adjacent samples and identical terrain shading across canvas resizes in both projections.

The sidebar reports cursor coordinates and bilinearly sampled native elevation in both projections. Double-click the map to pin a geographic location; Unpin resumes hover tracking. Pinned locations stay fixed while panning and zooming, and elevation refreshes as finer tiles arrive. Fullscreen has a top-right exit button as well as Escape. CPU/GPU tile storage shares the 256 MiB cache budget.

Hover and pinned locations have independent, labeled coordinate/elevation readouts with matching type sizes. Pinning leaves live hover enabled; both readout areas and their heading heights stay fixed to avoid layout shifts.
